# dropweb VPN на Keenetic — установщик (XKeen 2 + mihomo)

Один скрипт превращает Keenetic с Entware в **прозрачный VPN-роутер** для подписки dropweb: выбранные устройства (телик, ПК, телефон, приставка) ходят через VPN автоматически, без настроек на самих устройствах. Российские сайты идут напрямую — по правилам, которые приходят в подписке dropweb.

## Что вы получаете

- **Прозрачный VPN для выбранных устройств** через [XKeen 2](https://github.com/jameszeroX/XKeen) + **mihomo** (Clash.Meta) с правилами dropweb: TCP и UDP устройств из политики перехватываются роутером
- **Веб-панель «Выключить / Включить VPN»** на `http://192.168.1.1:8181/` — для тех, кто не любит SSH
- **Дашборд Zashboard** на `http://192.168.1.1:9090/ui/` — серверы, соединения, лог, пинг. API закрыт секретом
- **Обновление подписки раз в час** — конфиг сравнивается целиком, при изменениях применяется горячей перезагрузкой (без обрыва соединений)
- **Watchdog** — если mihomo упал, через минуту поднимется снова
- **Аварийное выключение** одной кнопкой или одной SSH-командой — и VPN **остаётся выключенным даже после перезагрузки**, пока сам не включишь

## Что нужно перед запуском

1. **Keenetic** с KeeneticOS 4+ и поддержкой Entware (Giga, Ultra, Hopper, Sprinter, Peak и т.п.)
2. **Entware/OPKG** на USB-флешке. Если нет — веб-интерфейс Keenetic → «Приложения» → поставить OPKG → перезагрузить роутер
3. **SSH** под root в Entware. По умолчанию `root@192.168.1.1`, пароль `keenetic`
4. **Ссылка на подписку из бота dropweb** — новая, вида `https://….apigw.yandexcloud.net/…`. Старые ссылки на `*.dropweb.org` **не подойдут**: этот домен блокируется в РФ, возьми свежую ссылку в боте

## Установка

```sh
ssh root@192.168.1.1
opkg update && opkg install curl
curl -fsSL -o /tmp/install.sh https://raw.githubusercontent.com/enkinvsh/dropweb-xkeen/main/install.sh
sh /tmp/install.sh
```

Скрипт спросит ссылку, покажет параметры и попросит подтвердить. Дальше всё сам: проверит подписку, поставит XKeen и mihomo, соберёт конфиг, запустит.

### Без вопросов

```sh
SUB_URL='https://…' sh /tmp/install.sh -y
```

Все параметры и переменные окружения: `sh /tmp/install.sh -h`.

### Повторный запуск = обновление

Запусти установщик ещё раз — он сохранит HWID и ссылку (Enter оставит прежнюю), обновит mihomo и перепишет конфиги и скрипты. С версии v1 настройки, включая HWID, переносятся автоматически — роутер не займёт новое место в лимите устройств.

## Что спросит скрипт

Только **ссылку на подписку** (и подтверждение). Остальное считается само и показывается в сводке перед установкой:

| Параметр | Откуда |
|---|---|
| HWID | Из MAC-адреса LAN роутера, сохраняется навсегда. Так роутер виден в боте dropweb как одно устройство |
| Модель (`x-device-model`) | Из `ndmc` — например «Keenetic Giga (KN-1011)» |
| Версия ОС (`x-ver-os`) | Версия KeeneticOS из `ndmc` |
| User-Agent | `clash.meta` |
| Порты | панель `8181`, API/дашборд `9090` |
| Секрет API | Случайный |

Любой параметр можно задать переменной окружения (`HWID`, `DEVICE_MODEL`, `PANEL_PORT`, `API_PORT`, `API_SECRET`, `LAN_IP`, …).

## Какие устройства идут через VPN

XKeen ищет в роутере политику доступа с именем **xkeen**:

- **Политики нет** — через mihomo идут **все** устройства сети. Это не страшно: российские сайты всё равно идут напрямую по правилам dropweb.
- **Политика есть** — через VPN идут **только** устройства, назначенные в неё.

Чтобы пускать через VPN только выбранные устройства:

1. Открой `http://192.168.1.1/` (логин/пароль роутера)
2. **«Приоритеты подключений»** → добавить политику с именем **xkeen**
3. **«Список клиентов»** → клик на устройство → политика доступа **xkeen** → «Сохранить». Повтори для каждого нужного устройства
4. Перезапусти XKeen: `ssh root@192.168.1.1 xkeen -restart`

Проверить, что политика есть:

```sh
ssh root@192.168.1.1 'curl -s 127.0.0.1:79/rci/show/ip/policy'
```

В ответе должна быть политика с `"description": "xkeen"`. Установщик в конце сам пишет, есть она или нет.

## После установки

```text
Веб-панель Вкл/Выкл :  http://192.168.1.1:8181/
Дашборд mihomo      :  http://192.168.1.1:9090/ui/
Адрес API           :  http://192.168.1.1:9090 (секрет — в итоге установки)
```

Секрет API и все настройки лежат в `/opt/etc/dropweb-xkeen/settings.env` (строка `API_SECRET=`). В конце установки скрипт печатает ссылку, по которой дашборд открывается сразу с секретом.

## Аварийные сценарии

### 1. Веб-панель → «⛔ Выключить VPN»

Один клик — mihomo гасится, перехват трафика снимается, **все устройства идут в интернет напрямую**. Выключение сохраняется: после перезагрузки VPN сам не поднимется, пока не нажмёшь «✅ Включить VPN».

### 2. SSH — если веб-панель не отвечает

```sh
ssh root@192.168.1.1 /opt/sbin/mihomo-panic.sh
```

Пароль: `keenetic`. Результат тот же, что у кнопки: VPN выключен и останется выключенным после перезагрузки. Включить обратно: `/opt/sbin/mihomo-resume.sh` или кнопка в панели.

### 3. Telnet в CLI Keenetic — если SSH мёртв

```sh
telnet 192.168.1.1
# admin / пароль от админки Keenetic
> system reboot
> yes
```

Учти: **после обычной перезагрузки (без panic) VPN поднимется сам** — так задумано. Если перед этим был выключен через панель или `mihomo-panic.sh`, он останется выключенным.

### 4. Выдернуть питание

То же, что перезагрузка: без panic VPN вернётся, после panic — нет.

**Не зажимай Reset на 10+ секунд** — это сброс Keenetic к заводским настройкам, сотрутся все настройки роутера.

## «Сервис вернул заглушку»

Значит, подписка вместо серверов отдала заглушку: исчерпан **лимит устройств** или HWID не принят. Что делать:

1. В боте dropweb → «Устройства» удали старое ненужное устройство
2. Запусти установку снова: `sh /tmp/install.sh`

HWID роутера печатается в сообщении об ошибке и хранится в `/opt/etc/dropweb-xkeen/settings.env`. Не меняй его без нужды — новый HWID займёт ещё одно место в лимите.

## Что внутри установки

| Файл | Назначение |
|---|---|
| `/opt/etc/dropweb-xkeen/settings.env` | Настройки: ссылка, HWID, порты, секрет API |

| `/opt/etc/mihomo/zash/` | Дашборд Zashboard |
| `/opt/sbin/update-mihomo-sub.sh` | Обновление подписки (cron раз в час) |

| `/opt/sbin/mihomo-panic.sh` | Аварийное выключение VPN |

## Удаление

```sh
ssh root@192.168.1.1 /opt/sbin/mihomo-vpn-uninstall.sh
```

Выключит VPN, удалит наши скрипты, панель, cron-задачи, конфиг и настройки. XKeen и mihomo остаются (с выключенным автозапуском) — если хочешь убрать и их:

```sh
ssh root@192.168.1.1 xkeen -remove
```

## Дизайн-решения

- **Hybrid: TCP через REDIRECT на `:1182`, UDP через TPROXY на `:1181`.** Порты задаются в `listeners`, а не через `redir-port`/`tproxy-port`. Причина — в шаблоне dropweb стоит `allow-lan: false`, и с ним верхнеуровневые порты слушают только `127.0.0.1`, а REDIRECT приносит трафик на LAN-адрес роутера — соединения отбивались. Записи `listeners` слушают `0.0.0.0` независимо от `allow-lan`.
- **TUN выключен.** TUN с auto-route на роутере ломает маршрутизацию всей сети; перехватом занимается XKeen через iptables.
- **`mixed-port` остаётся только для самого роутера** (`allow-lan: false`) — наружу в LAN SOCKS/HTTP-прокси не открывается. Им пользуется установщик для проверки выхода в интернет.
- **`find-process-mode: off`** — на роутере искать процесс-владельца соединения бессмысленно и дорого.
- **Обновление по содержимому.** Каждый час подписка скачивается, на неё накладываются наши правки, результат проверяется `mihomo -t` и сравнивается с текущим конфигом целиком. Есть разница — бэкап, замена и горячая перезагрузка через API; нет — ничего не трогается. Если подписка не скачалась или пришла заглушка — текущий конфиг остаётся.
- **HWID из MAC LAN, сохраняется.** Переустановка и обновление не плодят устройства в лимите; HWID от v1 переносится.
- **XKeen 2.0.1 Beta — только когда нужно.** Установка без вопросов (`xkeen -i auto`) есть только в 2.0.1 Beta. Сначала пробуется стабильная версия, Beta берётся, только если стабильная этого не умеет.
- **Killswitch XKeen выключен — fail-open намеренно.** Если mihomo упал, устройства лучше пусть временно идут напрямую, чем остаются без интернета; watchdog поднимет mihomo за минуту.
- **geoipset выключен** — все решения «через VPN или напрямую» принимаются правилами dropweb внутри mihomo, а не списками IP в iptables.
