# dropweb VPN на Keenetic — установщик (XKeen 2 + mihomo)

Один скрипт превращает Keenetic с Entware в **прозрачный VPN-роутер** для подписки dropweb: выбранные устройства (телик, ПК, телефон, приставка) ходят через VPN автоматически, без настроек на самих устройствах. Российские сайты идут напрямую — по правилам, которые приходят в подписке dropweb.

## Что вы получаете

- **Прозрачный VPN для выбранных устройств** через [XKeen 2](https://github.com/jameszeroX/XKeen) + **mihomo** (Clash.Meta) с правилами dropweb: TCP и UDP устройств из политики перехватываются роутером
- **Игры без лишнего пинга** — в mihomo попадает только тот UDP, который подписка может увести в VPN (QUIC, звонки Telegram/WhatsApp/Discord/Meet); игры и прочий UDP идут напрямую. Список роутер собирает сам из подписки, см. [«Игры и звонки (UDP)»](#игры-и-звонки-udp)
- **Сайты, которые обрывает провайдер, роутер находит сам** — если соединение напрямую виснет посреди загрузки, роутер проверяет сайт напрямую и через VPN и, если виноват провайдер, ведёт этот сайт через VPN. См. [«Сайты, которые обрывает провайдер»](#сайты-которые-обрывает-провайдер)
- **Веб-панель** на `http://192.168.1.1:8181/` — всё без SSH: VPN вкл/выкл, «Проверить связь», срок подписки, «Обновить подписку», смена ссылки. Если подписка упёрлась в лимит устройств или кончилась — панель так и пишет и даёт одну кнопку, которая это чинит
- **Дашборд Zashboard** на `http://192.168.1.1:9090/ui/` — серверы, соединения, лог, пинг. API закрыт секретом
- **Обновление подписки раз в час** — конфиг сравнивается целиком, при изменениях применяется горячей перезагрузкой (без обрыва соединений). Если основной адрес подписки недоступен, роутер берёт запасные адреса, которые dropweb присылает в самой подписке
- **Watchdog** — если mihomo упал, через минуту поднимется снова
- **Аварийное выключение** одной кнопкой или одной SSH-командой — и VPN **остаётся выключенным даже после перезагрузки**, пока сам не включишь

## Что нужно перед запуском

1. **Keenetic** с KeeneticOS 4+ и поддержкой Entware (Giga, Ultra, Hopper, Sprinter, Peak и т.п.)
2. **Entware на USB-флешке** — как поставить, см. [ниже](#entware-с-нуля)
3. **SSH** под root в Entware. По умолчанию `root@192.168.1.1`, пароль `keenetic` — смени его сразу после установки
4. **Ссылка на подписку из бота dropweb** — копируй её из бота целиком, адрес со временем меняется. Если установщик пишет, что подписка не скачалась, возьми свежую ссылку в боте

### Entware с нуля

Пункт «Приложения → OPKG» в веб-интерфейсе сам Entware **не ставит** — он только включает поддержку. Рабочий порядок (флешка будет стёрта):

1. Веб-интерфейс Keenetic → набор компонентов прошивки → поставь **«Поддержка открытых пакетов»** (OPKG), **файловую систему Ext** и оба пункта **модулей ядра Netfilter** (их требует XKeen). Роутер перезагрузится
2. Вставь флешку → в веб-интерфейсе открой её на странице USB-накопителей → **инициализировать / форматировать в EXT4** (Keenetic сам сделает раздел подкачки и EXT4). Запомни метку EXT4-раздела, например `EXT4-9jgJCLGS`
3. Открой командную строку роутера `http://192.168.1.1/a` и выполни одну команду — метка из шага 2, адрес под архитектуру роутера:

   ```text
   opkg disk EXT4-9jgJCLGS:/ https://bin.entware.net/aarch64-k3.10/installer/aarch64-installer.tar.gz
   ```

   | `arch` в `show version` | Адрес установщика |
   |---|---|
   | `aarch64` | `https://bin.entware.net/aarch64-k3.10/installer/aarch64-installer.tar.gz` |
   | `mipsel` | `https://bin.entware.net/mipselsf-k3.4/installer/mipsel-installer.tar.gz` |
   | `mips` | `https://bin.entware.net/mipssf-k3.4/installer/mips-installer.tar.gz` |

   Архитектуру покажет команда `show version` в той же командной строке (поле `arch`). Проверено на Netcraze Hopper NC-3811 (aarch64, KeeneticOS 5.1)
4. Через 1–3 минуты в журнале роутера появится «Установка Entware завершена». SSH: `ssh root@192.168.1.1`, пароль `keenetic`. Если в роутере стоит компонент «Сервер SSH», порт 22 занят им — смотри порт Entware в `/opt/etc/config/dropbear.conf`
5. Вход по ключу: Entware-шный dropbear берёт ключи root из `/opt/etc/dropbear/authorized_keys`, а не из `~/.ssh`

## Установка

```sh
ssh root@192.168.1.1
opkg update && opkg install curl
curl -fsSL -o /tmp/install.sh https://raw.githubusercontent.com/enkinvsh/dropweb-xkeen/main/install.sh
sh /tmp/install.sh
```

Скрипт спросит ссылку, покажет параметры и попросит подтвердить. Дальше всё сам: проверит подписку, поставит XKeen и mihomo, соберёт конфиг, запустит.

### Без вопросов

```sh
SUB_URL='https://…' sh /tmp/install.sh -y
```

Все параметры и переменные окружения: `sh /tmp/install.sh -h`.

### Повторный запуск = обновление

Запусти установщик ещё раз — он сохранит HWID и ссылку (Enter оставит прежнюю), обновит mihomo и перепишет конфиги и скрипты. С версии v1 настройки, включая HWID, переносятся автоматически — роутер не займёт новое место в лимите устройств.

## Что спросит скрипт

Только **ссылку на подписку** (и подтверждение). Остальное считается само и показывается в сводке перед установкой:

| Параметр | Откуда |
|---|---|
| HWID | Из MAC-адреса LAN роутера, сохраняется навсегда. Так роутер виден в боте dropweb как одно устройство |
| Модель (`x-device-model`) | Из `ndmc` — например «Keenetic Giga (KN-1011)» |
| Версия ОС (`x-ver-os`) | Версия KeeneticOS из `ndmc` |
| User-Agent | `clash.meta` |
| Порты | панель `8181`, API/дашборд `9090` |
| Секрет API | Случайный |

Любой параметр можно задать переменной окружения (`HWID`, `DEVICE_MODEL`, `PANEL_PORT`, `API_PORT`, `API_SECRET`, `LAN_IP`, …).

## Какие устройства идут через VPN

XKeen ищет в роутере политику доступа с именем **xkeen**:

- **Политики нет** — через mihomo идут **все** устройства сети. Это не страшно: российские сайты всё равно идут напрямую по правилам dropweb.
- **Политика есть** — через VPN идут **только** устройства, назначенные в неё.

Чтобы пускать через VPN только выбранные устройства:

1. Открой `http://192.168.1.1/` (логин/пароль роутера)
2. **«Приоритеты подключений»** → добавить политику с именем **xkeen**
3. **«Список клиентов»** → клик на устройство → политика доступа **xkeen** → «Сохранить». Повтори для каждого нужного устройства
4. Перезапусти XKeen: `ssh root@192.168.1.1 xkeen -restart`

Проверить, что политика есть:

```sh
ssh root@192.168.1.1 'curl -s 127.0.0.1:79/rci/show/ip/policy'
```

В ответе должна быть политика с `"description": "xkeen"`. Установщик в конце сам пишет, есть она или нет.

## Игры и звонки (UDP)

Правила dropweb решают «через VPN или напрямую» в основном по доменам. В UDP домена обычно нет: игры, голос и видеозвонки шлют пакеты прямо на IP. Если пускать в mihomo весь UDP, игры по правилам всё равно уходят напрямую, но с лишней задержкой на роутере: у PS5 пинг вырос с 80–100 до 150–200.

Поэтому роутер сам читает конфиг подписки и отправляет в mihomo только тот UDP, который правила могут увести в VPN:

- QUIC — UDP на порты, где mihomo узнаёт домен (сейчас 443): так YouTube и Instagram по QUIC идут по правилам, как и по TCP;
- адреса из IP-правил, которые ведут в VPN: Telegram, WhatsApp, Discord, Google Meet и всё, что dropweb добавит в подписку;
- диапазон fake-ip mihomo.

Весь остальной UDP — игры, PSN, Steam — идёт мимо mihomo обычным NAT. TCP это не касается. Список пересобирается при каждом обновлении подписки. XKeen при перезапуске стирает свою цепочку iptables, поэтому правило возвращает хук `netfilter.d`, а сторож раз в минуту проверяет, что оно на месте.

Если правила подписки нельзя свести к такому списку (например, последнее правило `MATCH` ведёт в VPN), обход выключается сам и весь UDP идёт через mihomo, как раньше. Итог установки пишет, что выбрано и почему. То же показывает:

```sh
ssh root@192.168.1.1 /opt/sbin/dropweb-udp-bypass.sh status
```

Пускать весь UDP через mihomo: `UDP_BYPASS=0` в `/opt/etc/dropweb-xkeen/settings.env`, потом `/opt/sbin/dropweb-udp-bypass.sh apply`.

## Сайты, которые обрывает провайдер

С 2025 года ТСПУ у российских провайдеров обрывает соединения со многими зарубежными серверами (Akamai, часть AWS/CloudFront, Cloudflare, Hetzner и другие): первые ~16 КБ проходят, потом ответы просто перестают приходить, без ошибки. Страница грузится наполовину, загрузка висит, игра пишет «Ожидание подключения к сети». Правила dropweb ведут незнакомые сайты напрямую, а готовые списки таких сайтов всегда отстают.

Поэтому роутер находит их сам (`/opt/sbin/dropweb-learn.py`, cron раз в минуту):

1. Смотрит соединения, которые mihomo ведёт напрямую по последнему правилу `MATCH`, и сокеты самого роутера: данные ушли, а ответа нет, или сервер замолчал посреди ответа — это подозрение.
2. Проверяет сайт сам, одним и тем же тестом напрямую и через VPN: серия запросов по одному соединению до 40 КБ, а если ответы маленькие — ещё отправка 64 КБ.
3. Напрямую застревает, через VPN проходит, и повторная прямая проверка снова застревает — сайт попадает в список `/opt/etc/mihomo/dxk-learned.txt`. Список подключён правилом `RULE-SET,dxk-learned,<VPN-группа>` прямо перед `MATCH`; mihomo перечитывает его без перезапуска, а зависшие прямые соединения к сайту роутер закрывает, и приложение переподключается уже через VPN.
4. Через VPN тоже не открывается — сайт просто лежит, в список он не попадает. Раз в неделю роутер проверяет найденные сайты напрямую: два удачных раза подряд — сайт убирается из списка.

Первый обрыв всё равно случается: от зависания до переключения проходит пара минут, потому что роутер ждёт, пока сервер точно замолчит. Проверок не больше трёх за минуту и 150 в сутки, в списке до 500 сайтов. VPN-группа — та, куда подписка чаще всего ведёт сайты (у dropweb это «🌍 VPN»); другую можно задать в `DPI_LEARN_GROUP`. Если подписка и так ведёт незнакомые сайты через VPN (`MATCH` не в `DIRECT`), поиск не нужен и выключается сам.

Найденные сайты видны в панели в разделе «Сайты через VPN»: там их можно убрать (убранный сайт роутер больше не добавит) и выключить поиск новых. То же по SSH:

```sh
ssh root@192.168.1.1 /opt/sbin/dropweb-learn.py status
ssh root@192.168.1.1 /opt/sbin/dropweb-learn.py probe example.com    # проверить сайт напрямую и через VPN
ssh root@192.168.1.1 /opt/sbin/dropweb-learn.py remove example.com   # убрать и больше не добавлять
ssh root@192.168.1.1 /opt/sbin/dropweb-learn.py allow example.com    # снова разрешить добавлять
```

Журнал — `/opt/var/log/dropweb-learn.log`. Не искать новые сайты: `DPI_LEARN=0` в `/opt/etc/dropweb-xkeen/settings.env` (уже найденные продолжают идти через VPN).

## После установки

```text
Веб-панель          :  http://192.168.1.1:8181/
Дашборд mihomo      :  http://192.168.1.1:9090/ui/
Адрес API           :  http://192.168.1.1:9090 (секрет — в итоге установки)
```

Секрет API и все настройки лежат в `/opt/etc/dropweb-xkeen/settings.env` (строка `API_SECRET=`). В конце установки скрипт печатает ссылку, по которой дашборд открывается сразу с секретом.

## Веб-панель

`http://192.168.1.1:8181/` — с любого устройства в домашней сети, без пароля и SSH.

- **VPN** — работает или выключен; переключатель с подтверждением
- **«Проверить связь»** — отдельно проверяет обычный интернет и VPN-сервер. Так видно, где беда: у провайдера, у сервера или в настройке
- **Подписка** — до какого числа оплачена, сколько дней осталось, когда обновлялась последний раз и не пришлось ли идти через запасной адрес
- **«Обновить подписку»** — скачать подписку прямо сейчас, не дожидаясь часа
- **«Сменить ссылку на подписку»** — вставить новую ссылку из бота. Панель сначала проверит её; если ссылка не рабочая, останется прежняя
- **«Обновление»** — какая версия стоит и вышла ли новая; «Обновить до …» сейчас и переключатель «Обновляться самому» (по умолчанию включён)
- **«Сайты через VPN»** — сайты, которые роутер сам перевёл в VPN, потому что провайдер обрывал их напрямую: когда и почему, кнопка «Убрать» и переключатель «Находить самому»

Если с подпиской что-то не так, сверху появляется подсказка с одним действием:

| Что пишет панель | Что нажать |
|---|---|
| Все места для устройств заняты | «Освободить место» — откроется кабинет dropweb со списком устройств. Вернись на вкладку панели — подписка обновится сама |
| Подписка закончилась | «Продлить подписку» — откроется кабинет dropweb |
| Подписка не скачалась | Проверь интернет; если не помогло — вставь свежую ссылку из бота |

### Как обновляется роутер

Обновления приходят из этого репозитория: новая версия выходит, когда в `main` поднимается `DROPWEB_XKEEN_VERSION` в `install.sh`. Роутер проверяет её каждую ночь и ставит сам; выключил «Обновляться самому» — только кнопкой в панели. Делает это `/opt/sbin/dropweb-xkeen-update.sh`:

1. Ветка переводится в коммит через GitHub API — сырые файлы GitHub кэширует на 5 минут, а по хэшу коммита отдаёт сразу свежие. `install.sh` и `panel/` берутся из одного коммита
2. Скачанный `install.sh` проверяется `sh -n`, `mihomo-panel.py` компилируется, в `index.html` должен быть `<html`
3. Снимок всего, что меняет установка (наши скрипты, mihomo, автозапуск, панель, настройки, конфиг, cron), — в `/opt/backups/dropweb-xkeen/snapshot`
4. Новый `install.sh -y` с той же подпиской и HWID. Выключенный в панели VPN остаётся выключенным
5. Проверка: mihomo и его API живы, правила XKeen на месте, интернет через mihomo есть (если был до обновления), панель отвечает
6. Не прошла — снимок возвращается на место, и версия помечается неудачной: ночью роутер её больше не ставит, ждёт следующую. Кнопкой можно попробовать ещё раз

Пока идёт обновление, сторож молчит, а страница панели показывает «Роутер обновляется» и перезагружается сама, когда всё закончилось. Итог — в `/opt/etc/dropweb-xkeen/update-state.env` (его показывает панель) и `/opt/var/log/dropweb-xkeen-update.log`.

Вручную, по SSH: `/opt/sbin/dropweb-xkeen-update.sh check` (узнать последнюю версию) или `run` (обновить сейчас).

Роутеры на 2.1.x ещё не умеют обновляться целиком: нажми там «Обновить панель», и в новой панели появится «Обновление».

Проверить свою ветку на роутере: в `/opt/etc/dropweb-xkeen/settings.env` поставь `UPDATE_URL='https://raw.githubusercontent.com/<user>/dropweb-xkeen/<ветка>'` и подними версию в `install.sh` этой ветки. Тот же `UPDATE_URL` понимает установщик (`UPDATE_URL=… sh install.sh`), `AUTO_UPDATE=0` — обновлять только кнопкой.

## Аварийные сценарии

### 1. Веб-панель → выключить VPN

Один клик — mihomo гасится, перехват трафика снимается, **все устройства идут в интернет напрямую**. Выключение сохраняется: после перезагрузки VPN сам не поднимется, пока не включишь его в панели.

### 2. SSH — если веб-панель не отвечает

```sh
ssh root@192.168.1.1 /opt/sbin/mihomo-panic.sh
```

Пароль: `keenetic`. Результат тот же, что у кнопки: VPN выключен и останется выключенным после перезагрузки. Включить обратно: `/opt/sbin/mihomo-resume.sh` или кнопка в панели.

### 3. Telnet в CLI Keenetic — если SSH мёртв

```sh
telnet 192.168.1.1
# admin / пароль от админки Keenetic
> system reboot
> yes
```

Учти: **после обычной перезагрузки (без panic) VPN поднимется сам** — так задумано. Если перед этим был выключен через панель или `mihomo-panic.sh`, он останется выключенным.

### 4. Выдернуть питание

То же, что перезагрузка: без panic VPN вернётся, после panic — нет.

**Не зажимай Reset на 10+ секунд** — это сброс Keenetic к заводским настройкам, сотрутся все настройки роутера.

## VPN пропал целиком и панель не открывается

Всё, кроме самого Keenetic, живёт на флешке. Если её извлекли, интернет идёт напрямую, а панель и SSH на порту 22 молчат.

- Проверь, что флешка вставлена в USB роутера. Вставил обратно — Entware, VPN и панель поднимутся сами за минуту-две, перезагружать не нужно.
- Кнопка FN на Keenetic по умолчанию отключает флешку одним нажатием. Установщик переносит это на удержание (3 секунды), а короткое нажатие ничего не делает. Если у кнопки на удержании уже было своё действие, установщик его не трогает: тогда флешку отключают только в веб-интерфейсе Keenetic.
- В веб-интерфейсе Keenetic (http://192.168.1.1) в разделе приложений и дисков флешка должна быть видна. Нет её там — порт или сама флешка.

## «Все места для устройств заняты» / «Сервис вернул заглушку»

Значит, подписка вместо серверов отдала заглушку: исчерпан **лимит устройств** или HWID не принят. Что делать:

1. Установщик печатает ссылку, где освободить место (страница «Устройства» в личном кабинете); то же самое — в боте dropweb → «Устройства». Удали старое ненужное устройство
2. Запусти установку снова: `sh /tmp/install.sh -y`. Если роутер уже установлен — просто нажми «Освободить место» в веб-панели, а потом «Обновить подписку»

HWID роутера печатается в сообщении об ошибке и хранится в `/opt/etc/dropweb-xkeen/settings.env`. Не меняй его без нужды — новый HWID займёт ещё одно место в лимите.

## Удаление

```sh
ssh root@192.168.1.1 /opt/sbin/mihomo-vpn-uninstall.sh
```

Выключит VPN, удалит наши скрипты, панель, cron-задачи, конфиг и настройки. XKeen и mihomo остаются (с выключенным автозапуском) — если хочешь убрать и их:

```sh
ssh root@192.168.1.1 xkeen -remove
```

## Дизайн-решения

- **Hybrid: TCP через REDIRECT на `:1182`, UDP через TPROXY на `:1181`.** Порты задаются в `listeners`, а не через `redir-port`/`tproxy-port`. Причина — в шаблоне dropweb стоит `allow-lan: false`, и с ним верхнеуровневые порты слушают только `127.0.0.1`, а REDIRECT приносит трафик на LAN-адрес роутера — соединения отбивались. Записи `listeners` слушают `0.0.0.0` независимо от `allow-lan`.
- **TUN выключен.** TUN с auto-route на роутере ломает маршрутизацию всей сети; перехватом занимается XKeen через iptables.
- **`mixed-port` остаётся только для самого роутера** (`allow-lan: false`) — наружу в LAN SOCKS/HTTP-прокси не открывается. Им пользуется установщик для проверки выхода в интернет.
- **`find-process-mode: off`** — на роутере искать процесс-владельца соединения бессмысленно и дорого.
- **Обновление по содержимому.** Каждый час подписка скачивается, на неё накладываются наши правки, результат проверяется `mihomo -t` и сравнивается с текущим конфигом целиком. Есть разница — бэкап, замена и горячая перезагрузка через API; нет — ничего не трогается. Если подписка не скачалась или пришла заглушка — текущий конфиг остаётся.
- **Запасные адреса подписки — из её же заголовков.** dropweb присылает `dropweb-sub-mirrors` и `fallback-url`; обновлятор запоминает их и идёт по ним, когда основной адрес не отвечает. Повторная установка и обновление dropweb-xkeen тоже берут запомненные зеркала, если основной адрес провайдер закрыл. Ссылку в настройках это не меняет.
- **Панель объясняет, а не логирует.** Каждый запуск обновлятора пишет итог (`updated`, `unchanged`, `device_limit`, `fetch_failed`, …) в `sub-state.env`; панель превращает его в одну фразу и одну кнопку.
- **Одна версия на всё и откат вместо надежды.** Панель живёт в своих файлах (`panel/`), чтобы её вид можно было менять, не трогая установщик, но обновляется вместе с остальным: так панель и скрипты на роутере всегда из одного коммита. Обновление — это обычная переустановка, а снимок до неё позволяет вернуть всё, если новая версия работает хуже.
- **HWID из MAC LAN, сохраняется.** Переустановка и обновление не плодят устройства в лимите; HWID от v1 переносится.
- **XKeen 2.0.1 Beta — только когда нужно.** Установка без вопросов (`xkeen -i auto`) есть только в 2.0.1 Beta. Сначала пробуется стабильная версия, Beta берётся, только если стабильная этого не умеет.
- **Killswitch XKeen выключен — fail-open намеренно.** Если mihomo упал, устройства лучше пусть временно идут напрямую, чем остаются без интернета; watchdog поднимет mihomo за минуту.
- **geoipset выключен** — все решения «через VPN или напрямую» принимаются правилами dropweb внутри mihomo, а не списками IP в iptables.
- **Обход UDP строится из правил, а не задаётся вручную.** Единственный список IP в iptables — тот, что роутер выводит из конфига подписки: dropweb меняет правила в шаблоне, роутер подхватывает их с обновлением подписки. Список берётся с запасом (лишний адрес в нём — это всего лишь пакет через mihomo, как раньше), а всё, что нельзя разобрать, выключает обход целиком, а не пропускает трафик мимо правил.
- **Сайт попадает в VPN только после проверки, а не по подозрению.** Зависшее соединение может значить что угодно: сервер лежит, приложение держит пустое соединение, плохой Wi-Fi. Поэтому роутер сравнивает один и тот же тест напрямую и через VPN и добавляет сайт, только если напрямую он застревает дважды, а через VPN проходит. Список отдельный от подписки и подключён перед `MATCH`, так что правила dropweb всегда главнее.
